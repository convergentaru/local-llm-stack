# Архитектура Wiki LLM

## Статус

Концепция и фундамент архитектуры будущей агентной компании.

Дата: 2026-10-08

---

## 1. Главная идея

Wiki LLM — не вспомогательная функция.

Это фундамент памяти будущей агентной компании.

Канонический источник знаний проекта — обычные Markdown-файлы.

Obsidian — человеческий интерфейс к этим файлам.

Wiki LLM — машинный интерфейс к тем же самым файлам.

Принцип:

    Markdown = Source of Truth
    Obsidian = Human Interface
    Wiki LLM = Machine Interface

Не должно существовать двух независимых копий знаний.

---

## 2. Архитектура знаний

    ОЛЕГ
      |
      v
    Obsidian
      |
      | редактирование
      v
    Markdown Wiki
      |
      +--------------------+
      |                    |
      v                    v
    Git              Wiki Index
                           |
                           v
                    wiki_search
                           |
                           v
                         Hermes
                           |

Markdown-файлы являются первичным источником.

Индекс является производным артефактом.

Если индекс уничтожен, он должен быть полностью восстановим из Markdown.

Не строить преждевременно сложную CMS или отдельную базу данных.

## 4. Metadata

Каждый значимый документ получает YAML front matter.

Пример:

    ---
    id: HERMES-ARCH-001
    title: Hermes architecture
    type: architecture
    status: active
    tags:
      - hermes
      - agent
      - runtime
      - local-llm
    related:
      - LLM-ARCH-001
      - WIKI-ARCH-001
    created: 2026-10-08
    updated: 2026-10-08
    ---

Минимальные поля:

- id
- title
- type
- status
- created
- updated
- tags
- related

Позже можно добавить:

- source
- confidence
- owner
- experiment
- decision
- supersedes
- superseded_by

## 5. Wiki Index

Первый этап поиска не требует embeddings.

Начальная реализация:

    Markdown
       |
       v
    parser
       |
       +--> metadata
       |
       +--> full text
       |
       v
    local index
       |
       v
    BM25 / full-text search
       |
       v
    wiki_search

Первый индекс должен быть:

- локальным;
- быстрым;
- простым;
- воспроизводимым;
- восстанавливаемым из Markdown.

Embeddings добавляются позже, только когда обычный поиск становится ограничением.

## 6. Hybrid Retrieval

Следующий уровень:

    query
      |
      +-------------------+
      |                   |
      v                   v
    BM25              embeddings
      |                   |
      +---------+---------+
                |
                v
             reranking
                |
                v
           wiki_search
                |
                v
          relevant chunks
                |
                v
              Hermes

Таким образом Wiki сможет находить как точные совпадения, так и смыслово близкие документы.

---

## 7. Два разных мира поиска

Критически важно не смешивать внутренние знания проекта и интернет.

Предлагаются два разных инструмента:

    wiki_search
        |
        v
    локальный Markdown Wiki
        |
        v
    знания проекта

и:

    web_search
        |
        v
    SearXNG
        |
        v
    Internet

SearXNG — внешний поисковый слой.

Wiki Search — внутренний поисковый слой.

Они должны оставаться концептуально разными.

---

## 8. Совместный поиск

Hermes при необходимости может использовать оба источника:

    query
      |
      +-------------------+
      |                   |
      v                   v
    wiki_search        web_search
      |                   |
      v                   v
    project             internet
    knowledge            sources
      |                   |
      +---------+---------+
                |
                v
             Hermes
                |
                v
          answer / action

Примеры:

"Что мы уже знаем?"

    -> wiki_search

"Что сейчас происходит во внешнем мире?"

    -> web_search

"Сравни наши данные с внешними источниками."

    -> wiki_search + web_search

---

## 9. Hermes как оркестратор

Hermes не должен быть самим Wiki.

Hermes должен использовать Wiki как один из инструментов.

Концептуально:

    Hermes
       |
       +--> wiki_search
       |
       +--> web_search
       |
       +--> terminal
       |
       +--> filesystem
       |
       +--> browser
       |
       +--> MCP
       |
       +--> Paperclip
       |
       +--> local LLM

Это превращает Hermes из интерфейса к LLM в исполнительный слой всей системы.

---

## 10. Obsidian

Obsidian не является отдельной базой знаний.

Obsidian открывает тот же каталог Markdown.

Человек работает через Obsidian.

Git видит обычные файлы.

Wiki Index индексирует обычные файлы.

Hermes получает знания через Wiki tools.

Таким образом:

    Obsidian
                              +--> Markdown <-- Git
          /
         /
    Wiki Index <-- Hermes

Все стороны работают с одним источником истины.

---

## 11. Git как история памяти

Git должен хранить историю изменения знаний.

Это позволяет:

- видеть историю;
- сравнивать версии;
- откатывать ошибочные изменения;
- отслеживать решения;
- восстанавливать старые состояния Wiki;
- синхронизировать знания между машинами.

Особенно важны:

    decisions/
    experiments/

Агентам необходимо знать не только текущее состояние системы, но и почему было принято определённое решение.

---

## 12. Wiki как память проекта

Wiki постепенно становится внешней долговременной памятью всей системы.

В ней должны появляться:

- архитектурные решения;
- конфигурации;
- модели;
- эксперименты;
- benchmark;
- проблемы;
- решения;
- инструкции;
- сведения о Hermes;
- сведения о Paperclip;
- MCP-интеграции;
- browser automation;
- результаты экспериментов;
- правила безопасности.

Но Wiki не должна превращаться в свалку.

Важный факт должен иметь источник, статус и возможность проверки.

---

## 13. Принцип "сначала память, потом агенты"

До построения сложной multi-agent системы необходимо построить слой знаний.

Иначе агенты будут:

- повторять уже сделанную работу;
- забывать решения;
- создавать противоречивые конфигурации;
- терять результаты экспериментов;
- не понимать архитектуру проекта.

Поэтому последовательность:

    1. Markdown Wiki
    2. Metadata
    3. Git
    4. Wiki Index
    5. wiki_search
    6. Hermes integration
    7. MCP
    8. Paperclip
    9. Browser
    10. Hermes -> Browser -> ChatGPT
    11. Voice

## 15. Один источник истины

Не строить множество разрозненных систем.

Строить один источник истины и множество интерфейсов к нему.

    Один Knowledge Source
             |
      +------+------+------+
      |      |      |      |
      v      v      v      v
   Human   Git    Search  Agents
  Obsidian        Index   Hermes

Markdown — фундамент.

Obsidian — окно человека в систему.

Wiki LLM — окно агента в систему.

Hermes — исполнительный слой.

SearXNG — окно во внешний интернет.

Paperclip — будущий слой управления организацией агентов.

Browser — мост к внешним интерфейсам.

ChatGPT — внешний интеллектуальный партнёр.

---

## 16. Первый MVP

Не строить всё сразу.

Первый MVP:

    docs/wiki/
        |
        +-- index.md
        +-- architecture/
        +-- models/
        +-- hermes/
        +-- experiments/
        +-- decisions/

Затем:

    Markdown
       -> metadata parser
       -> full-text/BM25 index
       -> wiki_search CLI/API

После этого:

    Hermes
       -> wiki_search

И только после успешного локального поиска:

    embeddings
       -> hybrid retrieval
       -> reranking

---

## 17. Связь с экспериментом Hermes -> Browser -> ChatGPT

Wiki является фундаментом эксперимента.

До браузерного моста Hermes должен понимать собственную систему:

- какие модели доступны;
- где находятся конфигурации;
- какие инструменты существуют;
- какие эксперименты проведены;
- какие решения приняты;
- какие ограничения есть у машины;
- как устроен Paperclip;
- как устроен browser layer.

Поэтому эксперимент:

    Олег
      |
      v
    Hermes
      |
      v
    Browser
      |
      v
    ChatGPT

должен рассматриваться не как отдельная игрушка, а как верхний уровень уже существующей архитектуры знаний и инструментов.

---

## 18. Философия системы

Система должна постепенно переходить от:

    "LLM отвечает на вопросы"

к:

    "Agent знает систему,
     понимает её историю,
     умеет искать знания,
     умеет искать внешний мир,
     умеет действовать,
     умеет проверять результат
     и умеет сохранять новый опыт."

Именно поэтому Wiki LLM — не вспомогательная функция.

Это фундамент памяти будущей агентной компании.
