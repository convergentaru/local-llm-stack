# JARVIS Work Augmentation — общая архитектура и предложения по развитию

> Цель — не делать костюм из фантастического фильма, а создать практичную рабочую систему, которая улучшает взаимодействие с компьютером и помогает выполнять физические задачи. Сначала — программные инструменты и эргономика, затем — датчики, физические прототипы и специализированное оборудование.

## Резюме

Рекомендуется развивать проект модульно. Не объединять в один эксперимент голографический вывод, EEG, жесты, электромиографию (EMG), физический экзоскелет и агента. У каждого модуля собственный критерий качества и безопасный интерфейс.

**Приоритетная последовательность:**

1. Надёжное цифровое ядро: Hermes, прямое подключение к выбранной локальной модели, задачи/статусы, локальная память и восстановленные навыки.
2. Обычный экран + голос + камера жестов: самые дешёвые способы ввода и вывода.
3. Рабочая станция для физических проектов: верхняя камера, освещение, держатель деталей/инструмента, пошаговая сборка и проверка BOM.
4. EMG-браслет как экспериментальный дополнительный ввод, если жестов и голоса недостаточно.
5. Pepper's Ghost / пространственный дисплей как сменный визуальный выход.
6. EEG/BCI как исследовательский канал, когда протоколы управления уже существуют.
7. Поддержка тела: сначала эргономические опоры и балансиры инструмента; экзоскелет только при доказанной необходимости для конкретных повторяющихся нагрузок.

## 1. Разделить систему на слои

    HUMAN INPUTS
    voice / keyboard / mouse / hand gestures / foot switch / optional EMG / experimental EEG
                         |
                         v
    INPUT ADAPTERS + CALIBRATION + CONFIDENCE FILTER
                         |
                         v
    LOCAL EVENT BUS (typed messages, timestamps, allowlist)
                         |
             +-----------+-----------+
             |                       |
             v                       v
    JARVIS UI / HUD             HERMES ADAPTER
    monitor / Pepper's Ghost     task request / status / confirmation
    spatial display (optional)          |
                                        v
                                  Hermes Agent
                                        |
                                        v
                                local inference endpoint

    PHYSICAL WORK SUPPORT (separate safety boundary):
    overhead camera / lighting / fixtures / tool holder / passive support
    optional exoskeleton evaluation, not controlled directly by free-form LLM output

Принцип: модель рассуждает и подготавливает намерение; проверенный исполнительный слой решает, разрешено ли конкретное действие. Сигнал камеры, EMG или EEG никогда не превращается напрямую в произвольную команду терминала.

## 2. Самое ценное улучшение: рабочее место для LEGO/робототехники

В контексте Robot Factory OS практический выигрыш может дать не экзоскелет, а «умный сборочный стол»:

- верхняя USB-камера для вида на рабочую поверхность;
- постоянное рассеянное освещение, чтобы части различались на кадре;
- небольшие лотки/контейнеры для деталей, маркированные по BOM;
- подставка/держатель для деталей и простой механический «third hand»;
- локальная веб-панель, где видны текущий шаг сборки, нужная деталь, количество, фото/схема и чек-лист;
- возможность голосом спросить: «Что дальше?», «Какая деталь 2×4?», «Проверь, верно ли собран этот узел?»;
- позднее — зрительное сопоставление камеры с эталонным изображением. Результат CV должен показываться как подсказка с уверенностью, а не как гарантированное доказательство правильной сборки.

Это направление относительно дешёвое, обратимое и сразу полезно для сборки LEGO Rover/механизмов и прототипирования.

## 3. Жесты — основа бесконтактного управления

Начать с RGB-веб-камеры и MediaPipe в обычном окне браузера. Жесты управляют только UI:

- pinch/drag — двигать или вращать 3D-объект;
- point — указать на элемент;
- open palm / fist held — безопасные команды pause/resume в пределах интерфейса;
- потеря трекинга или низкая уверенность — no-op.

Только после измерения ложных срабатываний добавить ограниченную навигацию по JARVIS HUD. Чувствительные операции по-прежнему требуют физической кнопки, явного голосового подтверждения или другого независимого подтверждения.

См. [JARVIS Holographic Interface](../jarvis-holographic-interface/README.md).

## 4. Рассмотреть EMG раньше EEG

**EMG (электромиография)** измеряет электрическую активность мышц, например мышц предплечья. Это не чтение мыслей: жест/напряжение мышц задаёт входной сигнал. Такой канал потенциально полезен, когда руки частично закрыты для камеры или нужно распознавать несколько намеренных движений.

Референс: [MyoMod/Armband](https://github.com/MyoMod/Armband) — открытый модульный six-channel EMG armband; проект описывает BLE, доступ к сырым и фильтрованным EMG-сигналам и IMU. Это аппаратный reference, а не готовая plug-and-play гарнитура для Ubuntu. Перед решением нужно проверить цену деталей, схему, лицензию, сборку и поток данных на нашей системе.

Порядок:

1. Не покупать плату немедленно.
2. Сначала оставить единый интерфейс событий, который можно тестировать генератором.
3. Затем оценить готовый совместимый EMG/IMU-источник или открытый MyoMod.
4. Проверить шум, повторяемость, утомляемость, калибровку и ошибки.
5. Допускать только whitelisted events вроде NEXT / SELECT / CANCEL / STATUS.

EEG/BCI оставить отдельной исследовательской веткой. Он может быть полезен для исследования альтернативных интерфейсов, но не должен быть обязательной частью ежедневного управления до измерения точности и false activation rate.

См. [JARVIS Neural Interface](../jarvis-neural-interface/README.md).

## 5. Голографический дисплей — это выход, а не мозг системы

Первый этап — обычное окно браузера с Three.js. Следом — Pepper's Ghost: четыре вида изображения на экране и прозрачный отражатель. Пространственный/light-field дисплей — необязательный апгрейд, только когда UI работает.

Не делать оптическую конструкцию точкой отказа: интерфейс должен оставаться пригодным на обычном мониторе. Любой 3D/HUD-экран — сменный renderer поверх одного API событий.

См. [JARVIS Holographic Interface](../jarvis-holographic-interface/README.md).

## 6. Экзоскелет: только под конкретную работу

Экзоскелет не улучшает компьютерный ввод автоматически. Его польза зависит от того, какую физическую задачу нужно облегчить.

### Для работы сидя, точной сборки или мелких LEGO-деталей

Сначала попробовать:
- правильно настроенный стол и стул;
- опору предплечий и запястий без ограничения естественного движения;
- поворотную/подвижную держалку для детали, камеры или инструмента;
- хорошее направленное освещение;
- лотки для деталей и пошаговый HUD.

Для точной работы сложный силовой экзоскелет может добавлять массу, люфт и ограничения движений; его польза здесь не очевидна без отдельного испытания.

### Для длительного удержания инструмента или работы выше уровня плеч

Здесь могут быть релевантны плечевые/верхнеручные экзоскелеты или держатели инструмента.

- [Fraunhofer IPA — Stuttgart Exo-Jacket](https://www.ipa.fraunhofer.de/de/aktuelle-forschung/biomechatronische-systeme/technologie-plattform-stuttgart-exo-jacket.html): исследовательский модульный exoskeleton с активной поддержкой сгибания/разгибания плеча и локтя для ручной работы; источник описывает переключатель помощи и исследования распознавания намерения по движениям/биосигналам.
- [Comau MATE-XT GO](https://www.comau.com/en/2026/02/11/comau-expands-wearable-robotics-with-the-new-mate-xt-go-exoskeleton/): коммерческий пассивный плечевой экзоскелет, представленный в 2026 году. Производитель заявляет массу менее 3 кг и снижение мышечного/ощущаемого усилия до 50% для повторяющейся и надголовной работы. Это данные производителя, а не гарантия для любого пользователя/задачи.
- [ALEX upper-body exoskeleton project](https://github.com/ualbertabiomed/exoskeleton): открытый проект верхнего экзоскелета, ориентированный на снижение повторяющейся нагрузки и обратную связь по осанке.
- [Upper-limb exoskeleton, ROS 2 + EMG](https://github.com/shehabhussien/upper-limb-exoskeleton): интересный инженерный reference с 7 степенями свободы, ROS 2, ESP32 и EMG, но публичный репозиторий следует оценивать как проект разработки, а не как готовое безопасное изделие.

### Риски

Нужна осторожность: у экзоскелета могут быть непредвиденные нагрузки, ограничения движения, точки защемления и другие риски. NIOSH/CDC отмечает потенциальные преимущества, но также необходимость изучать безопасность и эффективность по конкретным видам работы; многие исследования были небольшими и лабораторными.

Источники:
- [NIOSH/CDC: Industrial Exoskeletons](https://www.cdc.gov/niosh/bulletin/2020/industrial-exoskeletons.html)
- [NIOSH/CDC: Exoskeletons in Construction — benefits and challenges](https://www.cdc.gov/niosh/bulletin/2022/exoskeletons-construction.html)

**Не начинать с самодельного моторизованного экзоскелета.** Сначала определить, какая именно нагрузка повторяется, и оценить немоторизованную опору/держатель или готовое устройство с инструкциями, безопасностью и подтверждённым назначением.

## 7. Надёжность и безопасность — функциональная часть, не украшение

Для всей системы применить единые правила:

- каждый адаптер ввода имеет состояние enabled/disabled, confidence и timestamp;
- при пропаже сигнала действует no-op, а не повтор последней команды;
- разрешённый список событий явно задан;
- отдельное подтверждение для действий с файлами, аккаунтами, деньгами, внешними публикациями и запуском команд;
- физическая кнопка аварийной остановки/отключения — для любых будущих силовых устройств;
- журналы действий сохраняют, что система предложила и что человек подтвердил;
- локальный видеопоток и данные датчиков не публикуются и не отправляются в облако по умолчанию.

## 8. Рекомендуемый план

### Ближайший спринт — ничего не покупать

1. [ ] Восстановить и стабилизировать Hermes + локальную модель.
2. [ ] Создать рабочий HUD в обычном браузере.
3. [ ] Реализовать тестовый event bus и командный allowlist.
4. [ ] Подключить hand tracking и показать active task / status.
5. [ ] Создать сборочный UI для BOM/LEGO: текущий шаг, деталь, количество, подтверждение пользователем.

### Второй спринт — практическая эргономика

1. [ ] Определить конкретные операции, вызывающие усталость.
2. [ ] Подобрать простой держатель детали/инструмента и опору предплечий.
3. [ ] Протестировать надкамерную съёмку и освещение сборочной зоны.
4. [ ] Оценить, решает ли EMG-браслет реальную проблему, не дублируя жесты/голос.

### Позднее — аппаратные экспериментальные модули

1. [ ] Пространственный/Holographic renderer.
2. [ ] EMG prototype.
3. [ ] EEG/BCI classifier.
4. [ ] Пассивный/коммерческий exoskeleton evaluation для чётко определённого физического сценария.

## Решение

**Развивать не «костюм», а рабочую станцию с цифровым помощником и модульной физической поддержкой.** Наибольшая польза на первом этапе ожидается от общего интерфейса событий, надёжного голосового/жестового управления и камеры над рабочим столом. EMG — следующий разумный биосигнальный эксперимент. EEG и силовой экзоскелет остаются отдельными долгосрочными направлениями.

Это proposal, не подтверждение уже собранной или испытанной системы. Все аппаратные предположения подлежат тестированию на реальной Ubuntu и конкретной задаче.
