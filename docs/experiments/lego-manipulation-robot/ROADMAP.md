# Roadmap — LEGO Sequence-Kitting Robot

## Главный приоритет: комплектовка деталей по шагам инструкции

- [ ] Выбрать одну небольшую LDraw-модель/инструкцию и проверить, содержит ли она явную структуру шагов.
- [ ] Сформировать step-aware BOM: `step_index → part_id → colour → quantity`; сверить сумму деталей с общим BOM.
- [ ] Сгенерировать цифровой план лотков и dry-run без моторов.
- [ ] Инвентаризировать имеющиеся hubs, моторы, датчики, направляющие, Technic-механику и инструменты до покупки оборудования.
- [ ] Выбрать кассету для выходных ячеек: для начала — несколько пронумерованных ячеек/шагов, а не попытка сделать огромный сортировочный склад.
- [ ] Испытать повторяемый pick-and-place на ограниченном наборе известных деталей.
- [ ] Подключить проверку размещения и учёт: required / found / picked / placed / missing / unknown.
- [ ] Только после стабильного механизма добавить fixed overhead camera для идентификации ограниченного каталога деталей.
- [ ] Начать с деталей, разложенных одним слоем; обработку смешанной кучи/перекрытий считать отдельным этапом.
- [ ] Человек пока сам соединяет LEGO-детали по подготовленным лоткам.

Полная спецификация MVP, интерфейс задач и критерии готовности: [SEQUENCE-KITTING-ROBOT.md](SEQUENCE-KITTING-ROBOT.md).

## Механическая архитектура

- [ ] Исследовать портал X–Y–Z с верхней камерой как основной кандидат для повторяемой комплектовки по лоткам.
- [ ] Сравнить его с уже готовой LEGO EV3 Robot Arm H25; не покупать манипулятор до инвентаризации.
- [ ] Начать с простой сменной двухгубочной клешни, не с человеческой многопальцевой кисти.
- [ ] Предусмотреть аппаратный STOP/отключение питания приводов, ограничения хода и невысокую скорость.
- [ ] Отделить perception, планировщик комплектовки и низкоуровневый контроллер; LLM не управляет моторами напрямую.

## Последующий маршрут

- [ ] Добавить распознавание конкретных part ID из изображения, используя выбранную модель, LDraw references и реальные примеры.
- [ ] Обрабатывать unknown/ambiguous детали через ручную проверку, а не угадывать.
- [ ] Добавить сортировку из смешанной россыпи с учётом перекрытий и доступности захвата.
- [ ] Логировать точность идентификации, успех захвата, успех размещения и причины остановки.
- [ ] После доказанной комплектовки создать отдельный инструмент/режим для соединения кирпичика с фиксированной моделью.
- [ ] Для будущего соединения проверить сменные губки/прижимную насадку, приспособление для фиксации модели, ограничение усилия и проверку посадки.
- [ ] Тестировать соединение на одиночной паре деталей, затем на простом подузле. Не считать это готовностью собирать произвольную модель.

## Полезные готовые референсы

- [RegOrton/legosorter](https://github.com/RegOrton/legosorter) — компьютерное зрение и учёт part ID; hardware retrieval требует отдельной проверки.
- [Zekseed/PU-Robot](https://github.com/Zekseed/PU-Robot) — EV3 рука с клешнёй/датчиком цвета; вспомогательный механический референс.
- [LEGO EV3 building instructions](https://education.lego.com/en-us/product-resources/mindstorms-ev3/downloads/building-instructions/) — официальные исходные модели.
- [REFERENCE-DESIGNS.md](REFERENCE-DESIGNS.md) — сравнительная таблица существующих конструкций.

## Условия завершения MVP

- [ ] Программа создаёт по шагам корректный план лотков для выбранной модели.
- [ ] При нехватке детали или несоответствии BOM ошибка явно показана.
- [ ] На ограниченном физическом наборе измерены успех захвата, успех размещения, падения и столкновения.
- [ ] Человек может собрать тестовую модель по подготовленным лоткам.
- [ ] При потере камеры/связи, unknown part или выходе за пределы система останавливается безопасно.

## Пока не делать

- Не покупать дорогую многопальцевую руку до доказанного pick-and-place.
- Не считать датчик цвета распознаванием part ID.
- Не обещать захват произвольной детали из перекрывающейся кучи в первом прототипе.
- Не считать простую клешню достаточной для надёжного защёлкивания LEGO.
- Не давать Hermes произвольный доступ к моторам и safety limits.
