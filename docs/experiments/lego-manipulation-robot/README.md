# LEGO Sequence-Kitting Robot — комплектовка по инструкции

> Исследовательский проект Robot Factory OS. Первый результат — комплектовщик, который по готовой инструкции раскладывает LEGO-детали в порядке сборки; соединение деталей остаётся человеку. Позже исследуем распознавание смешанной россыпи и управляемое соединение кирпичиков.

## Почему это перспективно

Это не просто «рука робота». Для действительно полезной LEGO-системы нужны несколько совместно работающих подсистем:

1. **Идентификация детали:** цвет, форма, размеры, ориентация; в будущем — сопоставление с LEGO part ID / LDraw и BOM.
2. **Подача и фиксация:** известное место, где робот может надёжно взять одну деталь.
3. **Исполнительный механизм:** повторяемая система координат, подходящий захват и достаточная точность; для комплектовки первым кандидатом является портал X–Y–Z.
4. **Обратная связь:** камера проверяет результат захвата/помещения; в более сложном этапе — контакт/усилие проверяется отдельным датчиком или консервативной калибровкой.
5. **Планировщик работы:** BOM указывает нужную деталь и количество; сборочная инструкция задаёт последовательность.
6. **Безопасный исполнительный слой:** ограниченные движения, скорости, область работы, лимиты усилия/тока и аппаратная остановка.

Hermes может составлять план, объяснять ошибки и выдавать структурированное задание. Но низкоуровневое управление моторами должно оставаться у проверенного контроллера, а не напрямую у LLM.

## Приоритетная архитектура: комплектовка по шагам инструкции

Основной MVP описан в [SEQUENCE-KITTING-ROBOT.md](SEQUENCE-KITTING-ROBOT.md). Робот получает step-aware BOM, находит требуемые элементы, раскладывает их в подписанные ячейки последовательности, подтверждает результат и ведёт учёт недостачи. Сборку пока выполняет человек.

Для сортировочной рабочей зоны первым кандидатом является портал X–Y–Z с фиксированной верхней камерой и простой сменной двухгубочной клешнёй. Такая механика может позднее получить отдельную прижимную насадку для контролируемого соединения LEGO. Финальную конструкцию и приводы выбираем только после инвентаризации доступного оборудования.

[Zekseed/PU-Robot](https://github.com/Zekseed/PU-Robot) остаётся полезным референсом для клешни и датчика цвета, а не обязательной механической базой всего проекта. Сравнение готовых конструкций и официальных инструкций — в [REFERENCE-DESIGNS.md](REFERENCE-DESIGNS.md).

## Механика из имеющихся LEGO Technic деталей

До покупки отдельной руки проверим, можно ли собрать из имеющихся liftarms, frames, pins, axles и gears простой портал X–Y–Z или часть его направляющих и клешню. Сначала двигаем механизм вручную и проверяем геометрию; моторизацию добавляем только после того, как детали и ходы не заедают. Не предполагаем, что двухосевая рука автоматически подходит для комплектовки.

Цифровой конвейер: LDraw Nova для черновой CAD-идеи → сверка с реальным запасом → LPub3D для пошаговой инструкции на Ubuntu. AI-сгенерированная LDraw-модель требует механической проверки. Существующие документы о Technic-прототипе сохраняем как справочные варианты.

- [План LEGO Technic-прототипа без 3D-печати](LEGO-TECHNIC-PROTOTYPE.md)
- [Бюджет LEGO Technic-прототипа](LEGO-TECHNIC-BUDGET.md)

## Этапы проекта

### Этап 1 — цифровой план комплектовки

Для выбранной модели получить список деталей на каждом шаге, а не только сводную BOM. Проверить остатки, посчитать детали для каждой ячейки, сформировать последовательность выходных лотков и запустить dry-run без моторов.

### Этап 2 — физическая комплектовка на ограниченном наборе

Использовать заранее заданную рабочую область и небольшой набор известных деталей. Робот берёт деталь, кладёт её в ячейку нужного шага и подтверждает результат. Человек собирает модель вручную.

### Этап 3 — распознавание деталей камерой

Добавить fixed overhead camera, калибровку и распознавание только для известного каталога деталей. Начать с деталей, лежащих одним слоем; неизвестные/неоднозначные случаи передавать человеку.

### Этап 4 — смешанная россыпь

Расширить обработку перекрытий, сложных ориентаций и более широкого каталога. Не считать сортировку произвольной кучи решённой до независимых испытаний.

### Этап 5 — клешня для соединения деталей

Сохранить основу движения X–Y–Z, добавить сменные губки/прижимную насадку, фикстуру для модели и контролируемую проверку усилия. Вначале соединять одну простую пару деталей. Пяти-пальцевая рука не является условием MVP.

Подробная спецификация и критерии готовности: [SEQUENCE-KITTING-ROBOT.md](SEQUENCE-KITTING-ROBOT.md).

## Рекомендуемая архитектура

    LDraw model + step-aware BOM
                   |
                   v
    Kitting planner <---- stock/inventory ledger
                   |
                   v
    Perception / localization <---- fixed overhead camera
                   |
                   v
    Constrained task API
    - find_candidate(part_id)
    - pick(candidate_pose)
    - place(step_tray, slot)
    - verify_placement()
    - stop()
                   |
                   v
    X-Y-Z gantry + interchangeable gripper
                   |
                   v
    Step-labelled trays -> human assembly

Правило границы: Hermes не отправляет произвольные joint-angle массивы, shell-команды или прямые команды моторам. Он передаёт только валидированные задачи из ограниченного API. Контроллер проверяет workspace, скорость, допустимые позы и остановку.

## Как использовать имеющиеся проекты Robot Factory OS

Уже есть проектные направления, которые можно связать позже:
- механизм поршня и BOM в `ldraw-nova`;
- документация BrickGPT и Mesh2Brick;
- LDraw/reference models для определения детали и геометрии;
- Hermes + локальная модель для планирования и пояснений;
- Screenpipe для компьютерной истории и диагностики, но не как критичный контроллер реального времени;
- Obsidian/GitHub как документация, журнал испытаний и база процедур.

Нужно сохранять единую структуру part ID / количество / assembly step между BOM, визуальным распознаванием и роботизированным планировщиком.

## Как измерять прогресс

Для сортировки: accuracy по цветам и количество ошибок на 100 деталей.

Для pick-and-place: доля успешных захватов, успешных переносов, ошибок ориентации и среднее время цикла.

Для соединения: правильная посадка с первого раза, число повреждённых/сильно поцарапанных деталей, повторяемость и предел усилия. Отчёт должен содержать условия света, тип детали, gripper, скорость, калибровку и число попыток.

## Безопасность

- Начать без рук человека внутри рабочей зоны; оградить область движения.
- Установить аппаратную emergency stop / снятие питания приводов.
- Сначала ограничить скорость, область и усилия.
- Не разрешать LLM напрямую управлять моторами или отключать safety interlocks.
- При потере камеры, неизвестной детали, сбое связи или низкой уверенности выполнить остановку, не продолжать вслепую.
- Не начинать с силового защёлкивания или свободной работы многопальцевой кисти до тестов.
