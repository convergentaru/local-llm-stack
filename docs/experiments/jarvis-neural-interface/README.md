# JARVIS Neural Interface

> Исследовательский проект: локальный интерфейс «мозг — компьютер» для ограниченного управления JARVIS / Hermes с помощью классифицированных EEG-сигналов.

## Идея

Создать самодельный, по возможности недорогой и локально работающий BCI (Brain-Computer Interface), который сможет передавать несколько заранее определённых команд интерфейсу JARVIS, связанному с Hermes Agent.

Цель первого прототипа — не «читать мысли» и не преобразовывать произвольные мысли в текст. EEG-гарнитура регистрирует слабую электрическую активность, а программный классификатор пытается различать заранее выбранные состояния или реакции. Точность, задержку и частоту ложных срабатываний нужно измерять на реальных данных.

Изначально рассматриваем ограниченный набор команд:

- NEXT — перейти к следующему элементу интерфейса;
- SELECT — выбрать выделенный безопасный элемент;
- CANCEL — отменить текущий выбор;
- STATUS — запросить состояние JARVIS / Hermes.

Это предварительные семантические события, а не команды для произвольного исполнения shell-команд.

## Принципы проекта

1. **Local-first.** По возможности сигналы и их обработка остаются на локальном Ubuntu-компьютере; передача EEG в облако не требуется.
2. **Сначала измерения, потом автоматизация.** Сначала получаем и визуализируем сигналы, затем проверяем классификацию и лишь потом подключаем управление.
3. **Безопасность по умолчанию.** Не распознанный сигнал означает «ничего не делать». Любое действие с последствиями требует отдельного подтверждения.
4. **Ограниченный интерфейс.** Классификатор выдаёт только элементы белого списка; он не формирует произвольный код или команду терминала.
5. **Разделение компонентов.** BCI не должен зависеть от конкретной LLM. Hermes остаётся агентом, а JARVIS UI — клиентом и визуализацией состояния.
6. **Проверяемость.** Сохраняем версию модели классификации, настройки, набор тестов и метрики. Сырые EEG-записи храним только при осознанном решении, с понятными сроками удаления.
7. **Не медицинское устройство.** Это хобби-исследование интерфейса; проект не предназначен для диагностики, лечения или реабилитации.

## Предлагаемая архитектура

    EEG headset / DIY board
              |
              v
    acquisition: BrainFlow / LSL / device SDK
              |
              v
    signal quality + preprocessing
              |
              v
    classifier + confidence threshold + debounce
              |
              v
    local JARVIS BCI Bridge (allowlisted events only)
              |
              v
    JARVIS interface / approved Hermes control path
              |
              v
    Hermes Agent -> selected local model and tools

Точный способ управления Hermes со стороны моста будет выбран после восстановления базовой установки и проверки поддерживаемого локального интерфейса. На первом этапе используем демонстрационный UI или симулятор, не подключая классификатор к опасным операциям агента.

## Какие сигналы исследовать

Возможные подходы для экспериментального прототипа:

- **SSVEP:** выбор по зрительной реакции на визуальные стимулы с разными частотами. Может быть удобен для меню, но мерцающие стимулы могут вызывать дискомфорт и подходят не всем.
- **P300 / oddball:** обнаружение характерной реакции на редко появляющийся целевой стимул; требует калибровки и повторений.
- **Motor imagery:** классификация паттернов, связанных с мысленным представлением движения. Рассматривается как более сложная последующая ветка, а не гарантированная первая функция.

На первом этапе допустимо сравнить подходы на синтетических/демонстрационных данных; это не заменяет тестирование на реальных EEG-сигналах.

## Возможные аппаратные маршруты

1. **Без гарнитуры:** начать с симулированных событий и тестового UI. Это позволит построить мост, тесты безопасности и логику команд до покупки деталей.
2. **Готовое устройство:** подобрать совместимую EEG-гарнитуру с подтверждённой поддержкой Linux и доступом к потоковым данным. Совместимость Bluetooth и способ сборки драйверов следует проверять для конкретной модели.
3. **Самодельная плата:** исследовать open-source проект [Low-Cost-EEG](https://github.com/XavierAsghar/Low-Cost-EEG), основанный на ESP32-S3 и ADS1299. Это исследовательское оборудование, а не готовый сертифицированный продукт.

Подробности, сравнение вариантов и ограничения — в [HARDWARE.md](HARDWARE.md). Этапы реализации — в [ROADMAP.md](ROADMAP.md).

## Безопасность

Перед любыми испытаниями на человеке необходимо выполнить оценку электрической безопасности. Следовать инструкциям выбранной платы и изготовителя электродов; для рассматриваемого DIY-проекта Low-Cost-EEG автор требует аккумуляторное питание и отключённый USB-C во время подключения к человеку. Не подключать экспериментальную электрическую схему, электроды и USB к компьютеру вопреки инструкциям проекта.

На программном уровне:

- отсутствие уверенной классификации не создаёт событие;
- вводится порог уверенности, временная стабилизация и cooldown от повторных срабатываний;
- сначала разрешены только NEXT / SELECT / CANCEL / STATUS;
- действия, которые запускают произвольные инструменты, отправляют сообщения, изменяют или удаляют файлы, требуют отдельного явного подтверждения вне EEG-классификатора;
- доступ к EEG-потоку и журналам ограничивается локальным пользователем;
- сырой сигнал не отправляется во внешние API.

## Критерии первого полезного результата

Первый milestone считается выполненным, когда:

- проект запускается локально на Ubuntu;
- UI в тестовом режиме отображает поток событий;
- команды ограничены белым списком;
- неизвестный или нестабильный сигнал не запускает действие;
- измеряются ложные срабатывания и задержка;
- тесты подтверждают, что BCI-мост не может исполнить произвольную shell-команду.

## Полезные источники

- [Low-Cost-EEG: open-source hardware, firmware and Python host software](https://github.com/XavierAsghar/Low-Cost-EEG) — схема, BOM, firmware, поток BLE/LSL и предупреждение по электрической безопасности. Авторская лицензия проекта — GPL-3.0.
- [BrainFlow: Get Started / supported boards](https://brainflow.org/get_started/) — перечень поддерживаемых устройств и платформ.
- [BrainFlow supported boards](https://github.com/brainflow-dev/brainflow/blob/master/docs/SupportedBoards.rst) — документация по платам и требованиям Linux.
- [Lab Streaming Layer (LSL)](https://github.com/sccn/labstreaminglayer) — инфраструктура потоковой передачи временных сигналов.
- [OpenBCI](https://openbci.com/) — альтернативная экосистема открытого нейроизмерительного оборудования.

## Текущий статус

**Статус: research / planned.** На дату создания документа аппаратное устройство ещё не выбрано, классификатор не реализован, связь с Hermes не настроена. Следующий правильный шаг — создать симулятор событий и локальный UI, а затем сравнить аппаратные варианты.

Не покупать комплектующие и не собирать электрическую схему, пока не согласованы конкретная плата, электроды, электрическая безопасность и поддержка Ubuntu.
