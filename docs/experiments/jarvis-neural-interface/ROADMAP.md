# Roadmap — JARVIS Neural Interface

Связанный проект: [README.md](README.md). План намеренно разбит на небольшие этапы с проверяемыми критериями завершения.

## Этап 0 — спроектировать командный интерфейс

- [ ] Определить события: NEXT, SELECT, CANCEL, STATUS.
- [ ] Создать таблицу разрешённых действий и явно запретить произвольные shell-команды из BCI.
- [ ] Определить способ подтверждения чувствительных действий вне классификатора.
- [ ] Зафиксировать журнал событий без записи EEG по умолчанию.

**Готово, когда:** семантика команд и правила безопасности описаны и покрыты простыми тестами.

## Этап 1 — UI и симулятор без оборудования

- [ ] Создать локальную панель JARVIS BCI.
- [ ] Реализовать симулятор потока событий (клавиатура или генератор тестовых сигналов).
- [ ] Показывать выбранную команду, timestamp, confidence, статус и причину отклонения.
- [ ] Добавить кнопку аварийной остановки и выключатель BCI-моста.

**Готово, когда:** все события можно тестировать без EEG-оборудования, а запрещённые команды всегда отклоняются.

## Этап 2 — исследовать захват данных

- [ ] Сравнить BrainFlow и Lab Streaming Layer для выбранного устройства.
- [ ] Проверить Linux/Bluetooth/драйверные требования на конкретной гарнитуре.
- [ ] Начать с визуализации сигнала и оценки качества канала.
- [ ] Добавить безопасный режим записи тестовых данных с явным включением пользователем.
- [ ] Не подключать захват данных к реальному управлению Hermes.

**Готово, когда:** поток устойчиво читается, метки времени проверяются, качество сигнала и разрывы соединения видимы в UI.

## Этап 3 — классификатор

- [ ] Сравнить один выбранный парадигмальный подход (SSVEP, P300 или motor imagery).
- [ ] Отделить калибровочные данные от тестовых.
- [ ] Выбрать метрики: precision/recall для команд, false activation rate, latency, abstention rate.
- [ ] Ввести confidence threshold, debounce, refractory/cooldown window.
- [ ] Проверить поведение при плохом контакте, движении, помехах и пропадании потока.

**Готово, когда:** качество измерено на независимом тесте, а низкая уверенность приводит к состоянию NO-OP.

## Этап 4 — локальный BCI Bridge

- [ ] Принять только перечисленные типизированные события.
- [ ] Использовать локальный IPC/HTTP endpoint с loopback binding и проверкой источника.
- [ ] Добавить схему сообщений, версионирование, timeouts и rate limit.
- [ ] Не принимать произвольные URL, shell-команды, имена инструментов или скрипты из EEG-классификатора.
- [ ] Добавить отдельный лог событий и аварийный disable.

**Готово, когда:** bridge автоматически отклоняет неверные, повторные, устаревшие и неавторизованные сообщения.

## Этап 5 — интеграция с Hermes

- [ ] После восстановления Hermes выбрать документированный поддерживаемый локальный путь интеграции.
- [ ] Начать с отображения состояния и безвредной навигации, без выполнения произвольных действий.
- [ ] Добавить SELECT только для заранее разрешённых UI-элементов.
- [ ] Для опасных действий всегда требовать отдельное подтверждение.
- [ ] Проверить, что отключение BCI оставляет Hermes полностью управляемым обычными средствами.

**Готово, когда:** команды поступают в Hermes через проверенный интерфейс, а сбои BCI не блокируют обычное управление и не приводят к самопроизвольным действиям.

## Этап 6 — голос + HUD + дальнейшее развитие

- [ ] Совместить BCI с голосом, клавиатурой и указателем; не пытаться сразу заменить речь.
- [ ] Вывести состояние EEG, качество сигнала, confidence и текущую задачу в JARVIS HUD.
- [ ] Позже исследовать 3D/голографический интерфейс как отдельный модуль.
- [ ] Повторно оценить локальную приватность, логирование и политику хранения данных.

**Готово, когда:** несколько методов ввода могут работать совместно, а каждый из них можно отключить независимо.

## Первые задачи (приоритет)

1. [ ] Создать минимальный макет UI с симулированными NEXT / SELECT / CANCEL / STATUS.
2. [ ] Добавить единый обработчик команд с белым списком и тестами безопасности.
3. [ ] Выбрать аппаратный путь только после проверки поддерживаемых устройств, Linux и правил электрической безопасности.
4. [ ] Провести первый реальный эксперимент только в режиме наблюдения, без управления Hermes.

## Не делать пока

- Не покупать аппаратные компоненты до выбора конкретной схемы и проверки требований.
- Не разрешать EEG-классификатору вызывать shell, инструменты Hermes или действия с файлами напрямую.
- Не рассматривать эксперимент как медицинское или клиническое устройство.
- Не включать автоматическое сохранение сырого EEG без необходимости и понятной политики удаления.
