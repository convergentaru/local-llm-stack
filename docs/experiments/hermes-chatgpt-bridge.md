# Эксперимент: Hermes → Browser → ChatGPT

## Статус

**Черновик технического задания.**

Главный принцип: сначала построить Wiki LLM и систему структурированной долговременной памяти, затем документировать инфраструктуру и эксперименты, и только после этого переходить к эксперименту Hermes → Browser → ChatGPT.

---

## 1. Главная цель проекта

Построить локальную агентную инфраструктуру, в которой:

- знания проекта хранятся в структурированной Wiki;
- Wiki индексируется и доступна агентам через retrieval;
- Hermes используется как исполнительный и инструментальный слой;
- Paperclip используется для организации специализированных агентов;
- локальные LLM предоставляют вычислительные мощности;
- Browser предоставляет интерфейс взаимодействия с веб-сервисами;
- ChatGPT / Luna выступает внешним интеллектуальным партнёром.

---

# PHASE 1 — Wiki LLM / Knowledge Base

## 1.1. Главный принцип

До проведения сложных экспериментов необходимо создать систему, которая автоматически и последовательно документирует:

- архитектуру;
- конфигурацию;
- модели;
- инструменты;
- эксперименты;
- результаты;
- ошибки;
- решения;
- ограничения;
- изменения архитектуры.

Каждое существенное техническое решение должно иметь запись в Wiki.

Каждый эксперимент должен заканчиваться записью результата.

Неудачные эксперименты также документируются.

---

## 1.2. Структура Wiki

Предварительная структура:

    docs/wiki/
    ├── index.md
    ├── architecture/
    ├── models/
    ├── hermes/
    ├── paperclip/
    ├── browser/
    ├── mcp/
    ├── memory/
    ├── experiments/
    └── decisions/

Wiki должна оставаться обычным Markdown, чтобы её можно было:

- читать человеком;
- хранить в Git;
- индексировать;
- использовать локальными LLM;
- открывать через Obsidian;
- использовать Hermes;
- использовать Paperclip;
- переносить между системами без привязки к одному вендору.

---

## 1.3. Формат записи

Каждый документ должен иметь структурированные метаданные.

Минимальный набор:

- ID;
- title;
- type;
- status;
- created;
- updated;
- tags;
- related documents.

Основное содержание должно оставаться обычным Markdown.

Пример концепции:

    ---
    id: EXP-HERMES-001
    type: experiment
    status: draft
    tags:
      - hermes
      - browser
      - chatgpt
    ---

---

## 1.4. Индексация

Wiki не должна требовать загрузки всех документов в контекст модели.

Нужен механизм:

    query
      ↓
    index
      ↓
    relevant documents
      ↓
    relevant sections
      ↓
    LLM context

Цель:

**агент получает только необходимые знания.**

Необходимо исследовать варианты:

- SQLite FTS;
- BM25;
- embeddings;
- vector database;
- hybrid search;
- metadata filtering;
- graph/link traversal.

Предпочтительный первый вариант — максимально простой локальный индекс без внешней инфраструктуры.

---

## 1.5. Retrieval

Система должна уметь отвечать на запрос:

    "Как у нас настроен llama-swap?"

и находить соответствующую запись, не загружая всю Wiki.

Также:

    "Какие модели сейчас используются?"

    "Почему выбран Ministral?"

    "Какой порт LiteLLM?"

    "Что мы уже проверяли в Paperclip?"

    "Какие ограничения обнаружены у Hermes?"

---

## 1.6. Obsidian

Obsidian рассматривается как удобный человеческий интерфейс к той же Markdown Wiki.

Принцип:

    Markdown files
          ↑
          │
    ┌─────┴─────┐
    │           │
 Obsidian    AI agents
                │
        ┌───────┴───────┐
        │               │
      Hermes         Paperclip

Obsidian не должен становиться единственным хранилищем знаний.

Канонический источник — Markdown-файлы проекта.

---

# PHASE 2 — Документирование Hermes

После создания Wiki необходимо запустить Hermes и провести его полную инвентаризацию.

Задать Hermes один большой диагностический запрос.

Он должен перечислить:

- доступные инструменты;
- browser automation;
- MCP;
- terminal;
- filesystem;
- memory;
- session search;
- web;
- integrations;
- voice;
- delegation;
- внешние сервисы;
- ограничения;
- реально подключённые инструменты;
- инструменты, требующие дополнительной настройки.

Hermes не должен придумывать отсутствующие возможности.

Результат сохраняется в Wiki.

---

# PHASE 3 — Local LLM Stack

Рабочая архитектура:

    Hermes
       │
       ▼
    LiteLLM :4000
       │
       ▼
    llama-swap :8080
       │
       ├── Qwen
       ├── Ministral
       ├── DeepSeek
       └── другие локальные модели

Необходимо документировать:

- модели;
- GGUF;
- quantization;
- context size;
- GPU layers;
- RAM;
- VRAM;
- latency;
- назначение каждой модели.

---

# PHASE 4 — Paperclip

После создания Wiki и документирования Hermes провести эксперимент с четырьмя лёгкими моделями.

Цель:

- четыре специализированных агента;
- минимальное потребление памяти;
- независимые роли;
- tool calling;
- orchestration;
- обмен результатами;
- совместная работа с Wiki.

Необходимо измерять:

- RAM;
- VRAM;
- CPU;
- latency;
- стабильность;
- качество выполнения задач.

---

# PHASE 5 — Hermes как исполнительный слой

После исследования Hermes выбрать минимальную модель, которая достаточно хорошо выполняет:

- tool calling;
- многошаговые задачи;
- browser automation;
- MCP;
- работу с Wiki;
- работу с локальными инструментами.

Hermes не обязан использовать самую мощную модель.

Цель:

**минимальная достаточная модель.**

---

# PHASE 6 — Browser Automation

Исследовать подключение Hermes к локальному Chromium/Chrome через browser automation и CDP.

Сначала только безопасные тесты:

1. подключение;
2. открытие страницы;
3. navigation;
4. snapshot;
5. click;
6. type;
7. extraction;
8. возврат результата Hermes.

---

# PHASE 7 — Hermes → Browser → ChatGPT

Это основной эксперимент.

Целевая схема:

    Олег
      │
      ▼
    Hermes
      │
      ▼
    Browser
      │
      ▼
    ChatGPT / Luna
      │
      ▼
    Browser
      │
      ▼
    Hermes
      │
      ▼
    Олег

---

## 7.1. Гипотеза

Hermes может использовать браузер как коммуникационный мост между пользователем и веб-интерфейсом ChatGPT.

Это гипотеза, а не заранее гарантированная возможность.

---

## 7.2. Первый тест

Hermes должен:

1. открыть ChatGPT;
2. определить состояние страницы;
3. найти поле ввода;
4. отправить безопасный тестовый запрос;
5. дождаться ответа;
6. извлечь ответ;
7. передать его обратно пользователю.

---

## 7.3. Двусторонний тест

После успешного первого теста:

    User request
        ↓
      Hermes
        ↓
      Browser
        ↓
     ChatGPT
        ↓
      Browser
        ↓
      Hermes
        ↓
     Response

Каждый этап фиксируется в Wiki.

---

      ↓
     STT

    Hermes
      ↓
    Browser
      ↓

      ↓
    Voice

Голос не должен быть частью первого proof-of-concept.

Сначала доказать текстовый канал.

---

# PHASE 9 — Security

На первом этапе запрещены:

- банковские операции;
- покупки;
- удаление данных;
- изменение критических настроек;
- автоматическая публикация;
- передача секретов;
- действия с необратимыми последствиями.

Секреты, cookies, tokens и API keys не помещаются в Wiki и Git.

Все browser-эксперименты сначала выполняются на безопасных тестовых действиях.

---

# PHASE 10 — Автоматизация

После подтверждения архитектуры создать:

- start-stack.sh;
- stop-stack.sh;
- status-stack.sh;
- health-check.sh;
- wiki-index.sh;
- wiki-search.sh.

Все скрипты должны быть воспроизводимыми и безопасными.

---

# Конечная цель

Получить локальную агентную систему, в которой:

- знания не теряются;
- эксперименты воспроизводимы;
- Wiki доступна человеку и агентам;
- Obsidian предоставляет удобный интерфейс;
- Hermes выполняет действия;
- Paperclip управляет специализированными агентами;
- локальные модели обеспечивают inference;
- Browser связывает локальную агентную систему с веб-сервисами;
- ChatGPT / Luna может использоваться как внешний интеллектуальный партнёр.

**Первый приоритет: Wiki LLM.**

**Последний и наиболее интересный эксперимент: Hermes → Browser → ChatGPT.**
