# PravoAI: юридический поиск, embedding-модель и Hermes

## Что уже было задумано

В пользовательской инструкции по установке PravoAI описывался отдельный локальный проект по пути `~/projects/pravoai` и модель:

**Roflmax/bge-m3-russian-legal**

Важно: это embedding-модель для семантического поиска по русским юридическим документам, а не генеративная чат-модель. Она строит векторные представления текста, чтобы находить релевантные фрагменты. Юридическое объяснение и итоговый ответ продолжает формировать активная генеративная модель Hermes.

Источники:
- Карточка модели: https://huggingface.co/Roflmax/bge-m3-russian-legal
- Проект PravoAI в этой связке использует локальный корпус и MCP-инструменты для поиска.
- Официальные источники правовых актов РФ: https://pravo.gov.ru/ и https://publication.pravo.gov.ru/search

В карточке модели описаны эмбеддинги размерности 1024, поиск по русским юридическим документам и query-префикс для поиска. Перед установкой или обновлением сверяй фактическую модель, параметры и локальную документацию; не скачивай альтернативную модель автоматически.

## Архитектура

~~~text
Вопрос пользователя
    ↓
Hermes + текущая генеративная модель
    ↓ MCP
PravoAI: search_russian_law / get_corpus_status (если реально доступны)
    ↓
Локальный корпус документов + SQLite/vector index
    ↑
Roflmax/bge-m3-russian-legal — embedding / семантический поиск

GBrain — отдельная долговременная память агента:
хранит подтверждённые факты, рабочие процедуры и ссылки,
но не подменяет корпус нормативных актов.
~~~

Это три разных слоя, не смешивай их:
- **Генеративная модель Hermes** формирует ответ и использует инструменты.
- **PravoAI + legal embedding model** ищут потенциально релевантные фрагменты в юридическом корпусе.
- **GBrain** помогает помнить рабочие знания, ссылки и ранее проверенные процедуры между сессиями.

## Промпт для Hermes: аудит и запуск юридического контура

~~~ 
Задача: проверить и подключить существующий проект PravoAI к работающему Hermes, не ломая текущую модель, голос и рабочую конфигурацию.

Из предыдущей инструкции известно:
- ожидаемый каталог проекта: ~/projects/pravoai;
- embedding-модель: Roflmax/bge-m3-russian-legal;
- предполагаемые компоненты: Python 3, изолированное .venv, локальный корпус data/docs, SQLite/vector index;
- предполагалась интеграция через локальный stdio MCP-сервер;
- возможные инструменты: get_corpus_status и search_russian_law.

Это исторические ориентиры. Сначала проверь фактическое состояние файлов и инструментов.

Этап 1 — аудит:
1. Проверь, существует ли ~/projects/pravoai, его README/INSTALL_HERMES_RU.md, install.sh, download_model.py, ingest.py, server.py и локальная база.
2. Проверь текущую модель и runtime Hermes. Не меняй генеративную модель, провайдера, контекст или настройки голоса.
3. Установи, скачана ли Roflmax/bge-m3-russian-legal, где реально лежат веса, какое Python 3 окружение используется, доступен ли PyTorch/CUDA.
4. Не скачивай повторно существующие веса и не переустанавливай зависимости без доказанной необходимости.
5. Проверь каталог data/docs, наличие документов, metadata с источниками, локальный индекс и дату обновления.
6. Проверь конфигурацию MCP Hermes. Не создавай повторный ключ mcp_servers и не заменяй config.yaml целиком.

Этап 2 — проверить инструменты:
1. Подтверди, что Hermes действительно видит инструменты PravoAI.
2. Вызови get_corpus_status, если инструмент есть.
3. Выполни один тестовый search_russian_law по вопросу, на который в корпусе гарантированно есть документ.
4. Убедись, что результат включает название документа, фрагмент и источник/URL.
5. Если инструменты отсутствуют, сначала сообщи, что найдено и какие части отсутствуют. Предложи минимальный план исправления и backup; не внедряй новую интеграцию поверх неясной конфигурации.

Этап 3 — качество поиска:
1. Проверь, что запросы к Roflmax/bge-m3-russian-legal используют формат query, предусмотренный актуальной карточкой модели, включая нужный префикс, если он требуется.
2. Проверь, что обработка текста и параметры сегментации соответствуют установленной модели.
3. Не переиндексируй весь корпус, если для этого нет причины. Перед rebuild сохрани индекс и измерь доступные RAM/VRAM.
4. Не выполняй долгий GPU-тест одновременно с загруженной генеративной моделью, если это может вызвать OOM.

Этап 4 — безопасный юридический ответ:
1. Для каждого результата показывай первоисточник, название/номер акта, статью/пункт, редакцию и дату проверки, когда эти данные доступны.
2. Отделяй найденный текст от интерпретации модели.
3. Если документов недостаточно, прямо укажи это; не выдумывай статьи и судебные решения.
4. Проверь актуальность нормы в официальном источнике для конкретной юрисдикции. Для текущей российской правовой базы используй официальный портал правовой информации и источник публикации конкретного акта.
5. Перед реальным юридическим действием укажи, какие факты, даты, процессуальные сроки или документы необходимо дополнительно проверить.

Этап 5 — отчёт:
Укажи фактический путь проекта, модель и её состояние, число доступных документов/фрагментов (если инструмент может их сообщить), состояние MCP, результаты двух тестов, выявленные ошибки и безопасный следующий шаг.

Не называй интеграцию рабочей только потому, что конфигурация или файлы существуют. Не меняй модель и не перезагружай Hermes без необходимости.
~~~

## Промпт для отдельного юридического вопроса

~~~ 
Исследуй вопрос в пределах указанной юрисдикции с помощью PravoAI.

Юрисдикция/регион: [указать].
Факты и даты: [указать без лишних персональных данных].
Вопрос: [сформулировать].

1. Сначала проверь состояние корпуса и найди релевантные документы через доступный поисковый инструмент.
2. Для каждого результата укажи название, норму/пункт, URL первоисточника и редакцию/дату, если доступны.
3. Раздели результат на:
   A. что прямо следует из текста источника;
   B. что является толкованием;
   C. чего не хватает для вывода;
   D. что нужно проверить в официальном актуальном источнике.
4. Если локальный корпус не содержит нужного источника, сообщи об этом. Не делай вид, что поиск его нашёл.
5. Не придумывай номера статей, судебных дел, цитаты или URL.
6. Не представляй результат как окончательное юридическое заключение, если факты и актуальность норм не проверены.
~~~

## Связь PravoAI и GBrain

Не дублируй весь набор нормативных документов в памяти GBrain. Предпочтительная схема:

- Правовые документы, метаданные редакций и поисковый индекс живут в PravoAI.
- GBrain хранит ссылку на путь проекта, способ проверки корпуса, полезные проверенные процедуры и краткие заметки о том, как искать правовые источники.
- Hermes вызывает PravoAI для предметного поиска, затем формирует ответ с цитированием результатов.
- Публичный GitHub содержит только инструкции и незащищённые примеры. Частные юридические документы, данные клиентов и содержимое дел храни локально и с ограниченным доступом.

## Условия готовности

Не считать PravoAI готовым, пока не подтверждены фактическим тестом:
- локальный корпус не пуст;
- поиск выдаёт релевантный фрагмент;
- ссылка на источник сохранена и доступна;
- Hermes реально вызывает инструмент MCP;
- генеративная модель остаётся той же;
- извлечение найденных фрагментов можно повторить после перезапуска новой сессии.
