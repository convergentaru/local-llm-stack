# GBrain для Hermes: постоянная память между сессиями

## Назначение

GBrain — отдельный слой долговременной памяти и поиска знаний. Он не заменяет:
- краткую встроенную память Hermes;
- юридический индекс PravoAI;
- текущую генеративную модель;
- документацию в Git.

Рекомендуемое разделение:
- Hermes memory — компактные ключевые предпочтения и ссылки;
- GBrain — долговременные факты, проверенные процедуры и поиск между сессиями;
- PravoAI — семантический поиск по корпусу российских юридических документов;
- GitHub — проверяемые инструкции и история изменений.

## Важное перед запуском

Пользователь ранее сообщал, что GBrain уже устанавливался и запускался с Bun 1.4.3 и локальной PGLite-базой. Актуальная официальная инструкция GBrain указывает требование Bun 1.4.4 или новее. Это исторические сведения: проверь текущие версии, не предполагай, что они не изменились.

Это означает: сначала аудит существующей установки; не переустанавливать автоматически и не трогать базу до проверки резервной копии и версии.

Официальная актуальная инструкция:
https://github.com/garrytan/gbrain/blob/master/INSTALL_FOR_AGENTS.md

Важные моменты текущей инструкции:
- GBrain не следует ставить из одноимённого пакета npm; официальный источник — GitHub-проект garrytan/gbrain.
- Для локальной памяти без внешних ключей используется путь PGLite/no-embedding.
- На Hermes для регистрации MCP в актуальной инструкции описан hermes mcp add gbrain, а затем обязательная проверка hermes mcp test gbrain.
- Успешный exit code добавления не доказывает, что MCP реально подключился.
- PGLite работает как single-writer; два одновременно работающих сервера с одной базой или CLI-команда, которая открывает базу во время активного сервера, могут конфликтовать.
- После инициализации GBrain показывает решение для search mode и варианты выбора. Передай пользователю фактический режим и варианты выбора; не принимай за него окончательное решение молча.
- Writeback/сохранение фактов без отдельного запроса, автоматический захват сообщений, cron, autopilot, платное обогащение и внешние провайдеры не включать без явного согласования.
- Skillpack scaffold может скопировать больше 50 навыков. Не загружай весь комплект автоматически: сначала реши, какие навыки действительно нужны.

## Промпт для Hermes: подключить GBrain без потери текущей памяти

~~~
Задача: проверить и, если необходимо, починить интеграцию GBrain с текущим Hermes CLI. Это задача только про память; не изменяй контекст модели, endpoint, голос или модель.

Сначала прочитай актуальную официальную инструкцию полностью:
https://github.com/garrytan/gbrain/blob/master/INSTALL_FOR_AGENTS.md
Также изучи:
https://github.com/garrytan/gbrain/blob/master/AGENTS.md
https://github.com/garrytan/gbrain/blob/master/docs/mcp/HERMES.md

ЭТАП 1 — аудит:
1. Проверь команду gbrain, точный путь и версию; проверь Bun и его версию.
2. Проверь, откуда установлен пакет. Не запускай npm install -g gbrain и не заменяй работающую установку без причины.
3. Выполни только диагностические команды, подходящие текущей версии, например gbrain doctor --json. Сохрани вывод, удалив секреты.
4. Установи, где хранится база, какой backend выбран, каков её статус и есть ли резервная копия.
5. Прочитай фактическую конфигурацию Hermes MCP. Проверь, не зарегистрирован ли GBrain уже под другим именем и нет ли второго работающего сервера, использующего ту же PGLite-базу.
6. Сделай резервную копию данных и нужных конфигураций до любых изменений.

ЭТАП 2 — минимальная интеграция:
1. Если GBrain уже работает, не создавай новую базу и не меняй путь к существующей.
2. Если локальная база ещё не создана и это подтверждено, следуй актуальной официальной инструкции для memory-only setup. Для локального старта без embedding API в инструкции используется gbrain init --pglite --no-embedding.
3. Если Bun старше минимальной версии из актуальной инструкции, зафиксируй это до любых обновлений. Не выполняй обновление глобально без проверки последствий.
4. Для Hermes используй регистрацию MCP, указанную в актуальной инструкции; не переписывай вручную весь конфиг. Обязательно проверь реальное подключение через hermes mcp test gbrain и просмотри найденные инструменты.
5. Не запускай второй gbrain serve на той же базе, если первый процесс уже держит её.
6. Не устанавливай все 50+ навыков сразу. Начни только с минимально нужного набора и проверь, что Hermes действительно использует их.
7. Если первый запуск выводит решение по search mode, покажи пользователю фактически применённый режим и официальные варианты выбора/матрицу стоимости. Не скрывай это решение и не выбирай другой режим за пользователя. Можно продолжить безопасные диагностические шаги, но отметь, что выбор остаётся открытым.
8. Не включай автоматический захват всех сообщений, writeback без согласия, cron, autopilot, удалённый funnel, платные API или сторонние embedding/chat-провайдеры без отдельного согласования.

ЭТАП 3 — проверка памяти:
1. Выполни проверку MCP-инструментов, затем сохрани одну временную тестовую заметку с явным признаком install-check.
2. Извлеки именно эту заметку поиском и проверь, что источник/происхождение возвращаются корректно.
3. После теста заверши процесс штатно и повтори чтение из нового процесса/сессии, чтобы подтвердить долговременное хранение.
4. Удали только временную тестовую заметку поддерживаемым способом.
5. Убедись, что старая память и существующая база не потеряны.
6. Зафиксируй, какие механизмы автоматического writeback/захвата отключены и какие решения ещё ожидают пользователя.

ЭТАП 4 — отчёт:
Укажи версию Bun/GBrain, путь и backend базы, результат doctor, результат hermes mcp test gbrain, результат round-trip remember/recall из новой сессии и состояние backup. Не говори, что GBrain работает, если проверен только факт существования команды или конфигурационного файла.

Не переходи к созданию юридического корпуса или ремонту компьютеров в этой задаче. Сначала доведи до проверяемого результата один механизм памяти.
~~~

## Ожидаемый критерий готовности

GBrain считается подключённым только когда:
1. Hermes обнаруживает MCP-сервер и его инструменты;
2. тестовая запись сохраняется и находится по запросу;
3. запись извлекается после закрытия и повторного запуска процесса;
4. существующие данные остаются доступными;
5. автоматический сбор и внешние провайдеры остаются в согласованном состоянии;
6. search mode и writeback не включены молча вопреки решению пользователя.

## Как использовать память без раздувания контекста

Не помещай полную историю каждого диалога в системный prompt. Храни компактные факты с происхождением и подробные runbook-документы отдельно. При новой задаче Hermes должен сначала искать нужную запись, затем открывать только соответствующий документ, а не перечитывать всю базу целиком.
