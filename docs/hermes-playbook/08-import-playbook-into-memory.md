# Импорт Hermes Playbook в постоянную память

## Когда использовать

Используй этот промпт только после того, как Hermes стабильно отвечает на запросы и доступ к механизму постоянной памяти проверен. Не смешивай импорт базы знаний с диагностикой APIConnectionError.

## Промпт для Hermes

~~~
Задача: аккуратно добавить Hermes Playbook в постоянную память, чтобы в будущих сессиях ты знал, где искать проверенные процедуры. Не копируй всю документацию в краткую память.

Основной индекс GitHub:
https://github.com/convergentaru/local-llm-stack/blob/main/docs/hermes-playbook/README.md

Файлы:
- 01-context-window.md — диагностика контекстного окна и runtime.
- 02-api-connection-errors.md — диагностика custom provider и Connection error.
- 03-memory-recovery.md — восстановление постоянной памяти и сохранение решений.
- 04-hermes-upgrade-gbrain-legal-repair.md — общая архитектура развития Hermes, GBrain, ремонт компьютеров, юридические исследования и self-improvement.
- 05-operating-rules.md — последовательность и правила безопасности.
- 06-pravoai-legal-rag.md — PravoAI и Roflmax/bge-m3-russian-legal для семантического поиска правовых документов.
- 07-gbrain-memory-setup.md — проверка и подключение долговременной памяти GBrain.
- 08-import-playbook-into-memory.md — эта инструкция.

ЭТАП 1 — проверь механизм памяти:
1. Определи, какая постоянная память действительно загружается в текущей конфигурации Hermes.
2. Прочитай её содержимое и лимит. Сделай резервную копию перед редактированием.
3. Не повторяй прежнюю ошибку: ранее инструмент памяти сообщал 2303 символа при лимите 2200, а операции удаления и изменения не сработали.
4. Не удаляй полезные пользовательские сведения и не заменяй весь файл без анализа.

ЭТАП 2 — добавь только короткую запись:
Сохрани компактный указатель со следующими сведениями:
- подробные инструкции по Hermes хранятся в публичном репозитории local-llm-stack, docs/hermes-playbook/README.md;
- при проблеме контекста сначала сверять фактический runtime и не сбрасывать текущую рабочую конфигурацию без проверки;
- при APIConnectionError сначала собирать первичные журналы и проверить endpoint, не запускать повторные крупные задачи;
- GBrain — долговременная память; перед изменениями проверять текущую базу, резервную копию и реальное подключение MCP;
- PravoAI и Roflmax/bge-m3-russian-legal — отдельный юридический контур семантического поиска, не генеративная модель;
- использовать playbook по одному файлу и одной задаче за раз.

Не добавляй в память длинные промпты, полный журнал ошибок, частные правовые документы или дубли уже существующих записей.

ЭТАП 3 — проверить:
1. После записи проверь размер памяти.
2. Повтори чтение через штатный интерфейс памяти.
3. Если запись не сохраняется, не начинай бесконечные удаления. Зафиксируй точную ошибку, сохрани резервную копию и остановись.
4. Если в качестве памяти используется GBrain, сначала прочитай 07-gbrain-memory-setup.md и официальную инструкцию. Не запускай второй процесс для той же PGLite-базы. Перед выбором search mode покажи пользователю официальный список вариантов и не принимай решение за него.
5. Не включай автоматический захват разговоров, cron, autopilot или платные провайдеры без отдельного согласования.

В конце сообщи, какой механизм памяти использован, точный результат записи и чтения, размер до/после и путь резервной копии. Не утверждай, что память обновлена, если это не подтверждено проверкой.
~~~

## Принцип

Краткая память содержит указатели и важные предпочтения. Подробные инструкции остаются в GitHub. Не пытайся целиком поместить playbook в лимит памяти.
